# 全局协作与长程工程规则（RelayStudio Default AGENTS.md）

## 一、核心原则

- **结论与全景先行**：面向用户汇报时首段直给核心结论或解决方向；拆解复杂机制或软件工作流前，先用两三句话铺垫**全局版图**（它解决什么痛点、共有哪几个核心部分、整体如何配合），再展开局部细节。
- **深模块与接口契约视角**：聚焦系统各**模块**的对外职责、调用规则、输入输出与异常退路等**接口契约**（窄门进、深屋算、把错误定义出局）；3 项以上同类对比或并列故障归因优先使用表格。
- **求真、溯源与高噪上下文隔离**：
  - **一手信源核实**：核对本地状态与既定事实时，以源码、本机实测与官方文档为准，杜绝主观臆造。
  - **高噪上下文隔离与主从分流**：单点查证直接读取；涉及多文件源码、长报错日志或多工单实施时，主窗口作为“总调度官”只握上下文触发指针（Pointers），将编码、紧反馈测试与高噪排查并行派发给独立子代理——**网页端宿主优先直接派发网页端原生云端子代理**（不传模型或推理强度参数，直接复用同一条 MCP 隧道在本地独立 Worktree 读写与测试，**零本地额度消耗**；本地 CLI/IDE 宿主或需跨模型协同时按需调用本地 ACP 子代理）。子代理在后台保持高密度技术通信，仅向主窗口回传四行交接摘要。

## 二、单一事实源与技能路由（按当前任务自动取用 `engine-data/skills`）

- **需求澄清与成书阶段** → 依次调用 `grilling`（穷尽追问）、`to-spec`（凝固单一事实源 `SPEC.md`，锁定深模块接口契约与可替换接缝）、`to-tickets`（拆解为带前置阻塞边的曳光弹垂直切片工单或 `Expand → Migrate → Contract` 重构工单），并调用 `task_manage` 建立本地任务进度账本。
- **软件开发与测试实施阶段** → 主流程直读 `implement-spec` 技能（单张局部工单或单次直接开发需求按其内置分流规则调用 `implement`）：
  - 在独立工作树调用 `tdd`（红—绿—重构），修改期间紧反馈回路仅跑当前单测试文件，转绿后跑变更波及面测试，全量测试仅在集成分支收尾时运行一次；
  - 提交后调用 `code-review` 按编码规范（Standards）与生效规格（`Original Spec ⊕ Accepted Amendments`）执行双轴审查；
  - 遇同一根因连续 2 次失败且失败测试数未下降时，严禁死磕，立即执行**同因两次停手（`Status: Two-Strike-Stop`）**：回退至最近绿灯提交，在工单 `Attempt Log` 记录已试方案、反证报错与禁行约束，交由主窗口限次升级接力或标记 `Status: Quarantined` 隔离绕行，主会话绝不停机。
- **模块划分、网关断连恢复与慢测提速** → 直读 `engineering-decisions` 与 `codebase-design` 技能：
  - 遇到 60～120s 网关超时断流时，先查本机进程与 `run.json` / `pipeline.state.json` 终态收据，严禁盲目重发同一命令；
  - 遇到 `setup > 1s` 或全量回归长尾时，启用零冲突慢测提速三件套（4 进程按历史耗时从长到短排队并发、只读母版 `copytree`/`newContext` 秒拷、`> 60s` 超慢大文件外部 `manifest.json` 分包）。
- **棘手缺陷诊断与领域建模** → 分别调用 `diagnosing-bugs`、`domain-modeling`、`research` 与 `resolving-merge-conflicts` 技能。
