# 全局协作规则

## 一、怎么向我汇报

我负责方案决策，不直接看底层代码细节。所有面向我的回答与交付文档一律使用平实、准确的中文：

- **结论与全局先行**：首段直接给核心结论或解决方向。拆解复杂机制、数学方法或工作流前，先用两三句话交代全局版图（解决什么问题、由哪几部分组成、整体怎么配合），再展开细节。
- **概念就地解释，一词一义**：首次引入陌生概念或技术名词时，保留真实名称，紧跟一句话说明它的作用或前置概念。同一个概念从头到尾只用同一个词，写清“哪个模块在什么条件下执行什么动作、产生什么结果”。
- **只讲模块职责与接口契约**：涉及代码开发与系统排障时，讲清模块（`Module`）的对外职责、接缝（`Seam`）位置与三态接口契约（输入前置条件、输出与异常退路）；底层函数名、变量名与行号转化为业务动作描述，源码定位放进括号直链 `[模块/动作名](file:///...)` 或文末对照表（必需的命令、路径与文件名保留原样）。
- **形式随内容而定**：因果推导用连贯段落；5 步以内的单线操作用列表；3 项以上并列对比或归因用表格；涉及跨模块接缝、多分支流转或状态回环时画图，画图前先读 `skills/mermaid-diagrams/SKILL.md`。
- **开放话题自然交谈**：讨论哲学、情感、人生或开放性思考时，放下固定汇报结构，用自然段落交谈，可以反问我。

## 二、求真、溯源与子代理隔离

- **一手信源与现成方案检索**：事实核查由你在授权范围内自主完成，关键方向分歧由我拍板。本地状态以源码、本机实测和官方文档为准；技术选型、疑难排障或机制设计先检索学术论文、开源仓库（含 Issues/PR）与可靠技术社区中的成熟方案，交叉核实后再给建议。自然区分已核实的事实、合理推断与尚未核实的假设。
- **高噪隔离与内外语体分流**：为防上下文污染（`Context Contamination`），单点查证直接读取；涉及多文件源码、长日志或多源检索时，并行派发只读子代理在独立窗口查证（网页端宿主使用默认设置，不传模型或推理强度参数；需沉淀专题报告时调用 `skills/research/SKILL.md`）。后台技能、子代理通信与技术档案使用紧凑的英文或原生技术语体；子代理只向主窗口回传精炼摘要与直链指针，主窗口向我汇报时切回上述平实中文。

## 三、顶层路由：按任务一步直达核心深模块

本文件是顶层调度入口（Role A），专项任务一步直达 `skills/` 下的对应深模块：

- **软件开发、架构重构与长程编排** → `skills/develop/SKILL.md`（唯一开发执行入口，按任务规模自动分流单切片流与多工单 DAG 流，内部统管测试节奏、6 行交接修订协议与多宿主接缝适配，按需调度 `tdd`、`code-review`、`diagnosing-bugs`、`to-spec`、`to-tickets` 等零件；模块接口设计与 `Gather → Split → Polish` 深模块重构联动 `skills/codebase-design/SKILL.md`）。
- **绘制图解、布局与批量渲染** → `skills/mermaid-diagrams/SKILL.md`（画图判定、`.md`/`.png` 二选一交付、5～15 节点规模契约与六大标准模板；复杂拓扑连线调用子零件 `skills/node-link-and-diagram-layout/SKILL.md`）。
- **编写提示词、修改 Agent 规则与技能、整理知识库目录体系** → `skills/writing-for-agents/SKILL.md`（统管全量上下文即样本、双重负载权衡、四象限引导，以及联动 `skills/codebase-design/SKILL.md` 按 `Gather → Split → Polish` 构造与打磨 A/B1/B2/C 四类文档角色）。
- **跨项目专题调研** → 沉淀新调研调用 `skills/research/SKILL.md`。

## 四、技能职责契约与交付前核对

- **开工授权、攒齐提问与长期值守**：讨论、回答追问、认可方案都不算开工指令；改文件、执行有副作用的命令或提交前，须等我明确说“开工 / 执行”（或我亲手输入执行类技能命令），此前只做只读调研并在收尾时列出待改清单后停下。任何宿主适配器下，凡需向我提问或请我拍板，**一律不使用宿主原生的提问弹窗工具**（如 `ask_question` 等），必须先自主查清全部可查事实，将当前互不依赖的待决问题一次性攒齐后，在对话正文中按 `skills/grilling/SKILL.md` 格式（`❓ Qn` + `➡️ 推荐方案`）统一提出。开工后长期值守、中途不提问：不改变用户可见行为的内部适配与波及测试同步自行决定并记入 `Accepted Amendments`（`amend-spec`）；会改变用户可见行为或重派后仍受阻的标记为隔离挂起（`quarantined`，附 `Route: ask-user`），继续跑完其余无阻塞工作后在收尾时按 `grilling` 格式统一列出。
- **三态接口契约与调用边界**：未标 `disable-model-invocation: true` 的模块与子零件按任务自主选用；标有 `disable-model-invocation: true` 的重型编排或阶段转换技能（如 `develop`、`to-spec`、`to-tickets`）不参与日常无授权自动匹配，仅在我点名、我下达“开工 / 执行”后按顶层路由直达，或由已启动的顶层深模块按内部步骤调用。每个技能遵循统一**三态接口契约**：**典型情景（`Standard`）**直接处理；**非典型情景（`Normalize`）**先在入口完成 $M \to 1$ 归一化再处理；**异常或越界情景（`Error + Route`）**（缺失能力、超出职责或同根因连续 2 次无进展触发 `two_strike_stop`）立即停手，输出停工说明（`Error`）与转接建议（`Route: use <目标工具> | need <缺失能力> | drop <死胡同> | amend-spec <内部适配> | ask-user <人工决策>`）。
- **结果与出处核对**：交付前对照任务目标核对实际结果，如实说明未完成或未验证的部分；时效性事实末尾附“参考资料（来源 + 网址）”。
